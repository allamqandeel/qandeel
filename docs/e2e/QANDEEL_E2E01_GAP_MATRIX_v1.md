## 0. How to read a row

| Column | Meaning |
|---|---|
| **ID** | stable row identifier `E2E-<family>-NN`, family letters A–K as in the task's scope |
| **User moment / User goal** | what the user is doing and why, in the user's words |
| **Surface / Entry trigger** | where it happens and what starts it |
| **Existing Product decision** | what frozen authority already decides, cited |
| **Existing implementation** | `MOBILE EXISTS`, `BACKEND EXISTS` or `none`, with what exactly exists |
| **Visual status** | `PROOF EXISTS` (named proof) / `FROZEN VISUAL` / `UNDRAWN` / `PLACEHOLDER` |
| **Missing decisions** | Product decisions not yet made. `—` means none found |
| **Missing implementation** | what production work would be needed |
| **Operational Events Required** | APP-OPS-01 §5.1 domains the moment needs (codes in §2). `—` = not an operationally relevant moment |
| **Company Controls Required** | APP-OPS-01 §11 families the moment needs (codes in §2) |
| **Owner** | who owns closing the gap (codes in §3) |
| **Class.** | exactly one roadmap classification (§4) |
| **Bucket** | exactly one dependency bucket (§5) |
| **Evidence** | keys from §1 |

The rows name *which* events and controls a moment needs, inside APP-OPS-01 §5, §6 and §11. They design no schema,
no field and no event name (APP-OPS-01 §19, §21). Every event is content-free by law (APP-OPS-01 §6.2).

## 4. Classification rules applied

Exactly one of the roadmap's eight classifications per row ([ROADMAP] §3). No other lifecycle label is used.

| Classification | Applied when |
|---|---|
| `COMPLETE / PRODUCTION-READY` | the moment is decided, implemented on the production route with its frozen visual, and nothing remains. **No row qualifies** (master audit §3) |
| `DECIDED — NOT IMPLEMENTED` | frozen Product authority decides the moment's behaviour; no production surface exists. A hi-fi screen may still be undrawn — the `Visual status` column says so |
| `IMPLEMENTED — PRODUCT/VISUAL FINALIZATION MISSING` | production mobile code serves the moment today, but its frozen visual / copy / Product realization is not applied, or its Product wording was never decided |
| `PROOF ONLY` | the only user-facing realization is a proof that no closure froze |
| `PARTIALLY DEFINED` | some Product authority exists (often a Product-vision definition, placement-only, or runtime semantics) but the user-facing surface decisions are incomplete |
| `UNDECIDED` | no current record decides the moment |
| `COMPLETELY MISSING` | no decision, no proof, no implementation and no record naming it. **No row qualifies**: every moment the census walked is at least named by some record |
| `DEFERRED / PRE-LAUNCH` | a record deliberately defers the moment to a named later task or to release |

The Connected Worlds Product definitions (`[PDS]`, `[PDP]`, `[PDM]`, `[PDR]`) are Product Vision and state that they are
not an architecture freeze, not a visual freeze and not authorization to code. A Shared / Public / Replay / Matching moment
decided only there is therefore `PARTIALLY DEFINED`, never `DECIDED — NOT IMPLEMENTED`, unless a later frozen record
(I-08A4, P1, P3, G2.3, P4-C4) decides the user-facing part.

## 5. Dependency buckets applied

| Bucket | Applied when |
|---|---|
| `READY — PROVIDER-INDEPENDENT` | closable now without an AI / voice provider choice. It may still need a design proof, a copy approval inside frozen authority, or implementation authorization |
| `BLOCKED — VOICE RUNTIME / PROVIDER` | needs `QAN-BL-VOICE-01`, realtime media, ASR / TTS / voice provider or durable audio |
| `BLOCKED — ECONOMY / PROVIDER COST` | needs measured provider economics, Plans / Credits or usage policy |
| `STANDALONE OWNED` | already belongs to a separate named task or phase (`LANTERN`, `SEC-01`, `CTX-01`, `CW-I08`, `CW-I09`) |
| `PRE-LAUNCH ONLY` | correctly deferred to release hardening, device, store, legal or operational work |
| `PRODUCT OWNER DECISION REQUIRED` | a genuine Product decision is missing and cannot be inferred from frozen authority |

A Model Router with real provider adapters already exists behind the Product ([API-MR]); the choice among them is
deferred (QIR-001) and coupled to the audit's benchmark ([ROADMAP] §3). A text surface that sends turns through the Model
Router is therefore provider-*independent*: the provider choice changes response quality and cost, not the surface.
