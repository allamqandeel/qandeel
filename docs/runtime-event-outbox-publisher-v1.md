# Runtime Event Outbox + Publisher v1

Conversation terminal state and its event are committed by one PostgreSQL RPC transaction. V1 produces only `ConversationTurnCompleted`, `ConversationTurnFailed`, and `ConversationTurnCancelled`; Redis is never contacted by the interactive path.

Each immutable envelope has a stable server UUID, version `1.0`, database transaction time, producer, opaque user/session/source-turn IDs, optional QANDEEL request and orchestration correlation, `SENSITIVE` classification, schema reference, `contains_content=false`, and `OPERATIONAL_EVENT_V1` retention. Payload keys are limited to opaque IDs, terminal status, processing path, bounded routing reason, and optional orchestration ID. Conversation text, provider data, prompts, Memory/HIM data, credentials, request bodies, and idempotency keys are prohibited.

The internal publisher uses `SUPABASE_URL` plus `SUPABASE_SERVICE_ROLE_KEY`; end-user roles have no outbox table access or publisher RPC execution. Every definer RPC has an empty search path, explicit `postgres` ownership, an explicit PUBLIC/anon/authenticated revoke, and then only the narrow required role grant. Terminal RPCs additionally enforce `auth.uid() = p_user_id`. `REDIS_URL` is also required. If either boundary is absent, or startup fails, the API continues and durable events remain pending. Since Startup Recovery v1, a failed Redis startup connection no longer ends delivery for that instance: the live publisher keeps its single supervision cycle on the same `RUNTIME_EVENT_POLL_MS` cadence, retries the transport connection before any claim, never claims outbox rows while the transport is unavailable, and resumes publishing automatically when Redis returns (see `runtime-event-publisher-startup-recovery-v1.md`). The optional `RUNTIME_EVENT_STREAM` defaults to `qandeel:runtime-events:v1`; `RUNTIME_EVENT_POLL_MS` controls bounded polling. Tests never start polling.

Workers atomically claim due `PENDING`/`RETRY` or expired `IN_FLIGHT` rows with `FOR UPDATE SKIP LOCKED`. Every claim has a fresh token and lease. Ack, retry, and quarantine require the matching event ID and claim token, fencing stale workers. Redis Streams `XADD` carries `event_id` and the sanitized canonical envelope. Delivery is at least once; consumers deduplicate by stable `event_id`. Transient failures use bounded exponential backoff. Invalid events and exhausted attempts are quarantined, never deleted.

Before transport, the publisher structurally validates the event type/version/schema mapping, UUID identities, required exact payload shape, terminal-state mapping, subject/payload identity equality, bounded processing/routing values, and the no-content flag. Bounded operational metrics record only operation, outcome, and the fixed `redis_streams` transport; identifiers, payloads, endpoints, credentials, and raw errors are never dimensions. Telemetry is fail-soft and cannot change claim, publish, ack, retry, or quarantine behavior.

## Reconciliation status

Health / Readiness / Dependency Probes v1 was completed after this outbox foundation and now reports the Runtime Events subsystem as an optional operational dependency using local publisher/transport state. Health probing does not publish events, claim outbox rows, retry, acknowledge, quarantine, or change delivery semantics.

Deferred event domains include session-start, received/context/routing/provider events, Memory, HIM, proactive, voice, commerce, and consent/deletion propagation. V1 still does not implement inbox workflows, Kafka, RabbitMQ, NATS, or an event-driven runtime rewrite.
