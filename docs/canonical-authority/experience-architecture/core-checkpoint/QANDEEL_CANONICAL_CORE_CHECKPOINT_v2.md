# 3. Frozen Stage 3 / Stage 4 World Model

## S34-WORLD-01 — One persistent world
**Status:** FROZEN

There is one canonical Living Analysis Map. Historical, live, focused, inspected, mobile, and zoomed states are views/projections of the same world — not alternate maps.

## S34-WORLD-02 — Organic Living Field
**Status:** FROZEN

Stage 3 visual direction is the **Organic Living Field / Nebular World**. Proof-board boxes, labels, grids, debug marks and architectural annotations are scaffolding only and are not final visual language.

## S34-WORLD-03 — Canonical disclosure hierarchy
**Status:** FROZEN

```text
World
→ Thread
→ Session
→ Reading / analytical object
→ Source / Provenance
```

Semantic Zoom is disclosure, not ordinary geometric magnification.

## S34-WORLD-04 — Pan
**Status:** FROZEN

Pan moves the camera through the same canonical geography. It does not move temporal state, manufacture meaning, relocate objects, or create an alternate layout.

## S34-WORLD-05 — Persistent Home loci
**Status:** FROZEN

Established Threads have persistent Home loci. Projection changes do not recompute established spatial commitments.

```text
Home(e, t >= establishment) = constant
```

This does not mean every canonical object owns an independent world-space coordinate. Readings, Memories, Events, Relations, Evidence participations, Confidence states, Questions and ordinary contextual appearances disclose within their frozen semantic/contextual structure.

## S34-WORLD-06 — Geometry cannot manufacture meaning
**Status:** FROZEN

Geometry, spacing, size, clustering, proximity or alignment must not silently imply importance, confidence, truth, causality, ownership, analytical strength, or future emergence.

## S34-WORLD-07 — Canonical identity across contexts
**Status:** FROZEN

One canonical object may have multiple legitimate contextual appearances. Contextual appearance does not duplicate canonical identity, create ownership, or automatically create a relation.

## S34-WORLD-08 — Mobile parity
**Status:** FROZEN

Mobile/narrow projection may reduce simultaneous disclosure. It must not reflow canonical geography or create different truth, identity, or temporal semantics.

# 4. Stage 5.1 — Temporal State + Map Orientation

## S5-STATE-01 — Canonical state
**Status:** FROZEN

```text
S = { LH, LF, TM, TC, K(TC), IF, MC, RH }
```

- `LH` — Live Head.
- `LF` — current Live Focus.
- `TM` — temporal mode.
- `TC` — effective temporal cursor.
- `K(TC)` — then-legitimate projection of the same world.
- `IF` — inspected focus / exact inspection reference.
- `MC` — Map camera + semantic depth.
- `RH` — reversible navigation/inspection history.

No third temporal mode or additional canonical state member was required by Stage 5 freeze.

## S5-STATE-02 — Temporal modes
**Status:** FROZEN

```text
TM ∈ { FOLLOW_LIVE, PINNED(t) }

FOLLOW_LIVE → TC = LH
PINNED(t)   → TC = t
```

Only explicit temporal navigation establishes or changes a pinned `TC`. The sole automatic exception is `FOLLOW_LIVE`, where effective `TC` advances because `LH` advances.

Pan, Semantic Zoom, inspection, contextual navigation and spatial direct jumps do not silently move `TC`.

## S5-TIME-01 — Distinct temporal facts
**Status:** FROZEN

- `SP(x)` — current-session Session Position.
- `RTO(x)` — Referenced Temporal Origin.
- `KF(x)` — earliest legitimate knowledge availability of the relevant identity/object/version/state/appearance.
- `VF(x_v) / VT(x_v)` — then-current validity interval where applicable.

```text
Referenced time ≠ Timeline position
Knowledge availability ≠ version validity
Superseded ≠ forgotten
Known ≠ necessarily then-current
```

## S5-PROJ-01 — Historical projection
**Status:** FROZEN

```text
K(t) = Project(W, t)
```

Historical projection preserves canonical identity and established spatial commitments, shows only then-legitimate knowledge/state, never borrows later truth backward, and never compacts/recenters/relayouts history.

## S5-PROJ-02 — Future-unavailable means absent
**Status:** FROZEN

Future-unavailable material gains no ambient/default representation: no ghost, dimmed future node, lock, placeholder, disabled future item, label, count, spatial target, direction, future-shaped slot, or intentional future-shaped hole. Natural empty field is allowed.

## S5-RH-01 — Exact temporal restoration
**Status:** FROZEN

```text
RestoreTemporal(checkpoint)
:= PINNED(checkpoint.capturedTC)
```

This applies even when the checkpoint was captured while `FOLLOW_LIVE`. `capturedTM` may remain provenance only. Only explicit Return to Live Head re-establishes `FOLLOW_LIVE`.

# 5. Stage 5.2 — Timeline Navigation Grammar

## S5-TL-01 — Timeline domain
**Status:** FROZEN

The Stage 5 Timeline is a **current-Session temporal navigator only**.

```text
M_current = { m0 < m1 < ... < LH }
```

Past Sessions remain Map footprints. No cross-session/life-history Timeline exists in Stage 5.

## S5-TL-02 — Two target kinds
**Status:** FROZEN

```text
Moment(m)
LIVE_EDGE
```

```text
Commit(Moment(m)) → PINNED(m)
Commit(LIVE_EDGE) → FOLLOW_LIVE
```

Target kind controls intent even when coordinates match. Thus `Moment(LH) ≠ LIVE_EDGE`.

## S5-TL-03 — Preview / Commit / Settle
**Status:** FROZEN

```text
Preview → Commit → Settle
```

`PTC` is transient interaction status and:

```text
PTC ∉ S
```

Preview writes no RH, does not silently commit, and is not a persistent mode.

## S5-TL-04 — Spatial input cancels Preview
**Status:** FROZEN

A deliberate Pan / Zoom / inspection action during Preview:
1. cancels Preview;
2. discards `PTC`;
3. preserves committed `TM/TC`;
4. then executes the Stage 4 action.

No implicit temporal commit occurs.

## S5-TL-05 — Temporal intent ≠ spatial intent
**Status:** FROZEN

Temporal navigation does not imply camera movement. Spatial movement requires explicit locate authority. No persistent Timeline↔Camera follow exists.

## S5-TL-06 — P3 settle-time locate
**Status:** FROZEN

```text
UniqueLocatable(x, K(TC))
```

At settle:
- 1 locus → locate once;
- 0 loci → no camera move;
- >1 loci → explicit contextual choice.

A later human context choice after a multi-locus result is a separate explicit transaction.

# 6. Stage 5.3 — Timeline Disclosure + Temporal Legibility

## S5-DISC-01 — Timeline semantic boundary
**Status:** FROZEN

> **The current-session Timeline discloses temporal orientation and the minimum committed anonymous conversational structure needed for temporal legibility. It does not disclose analytical interpretation.**

The Map remains the semantic destination.

## S5-DISC-02 — Map-only analytical meaning
**Status:** FROZEN

Map-side / semantic inspection material includes:
- Readings;
- relations;
- Evidence participation;
- Questions / Information Gaps;
- corrections / supersession;
- analytical interpretation.

Confidence-over-time is forbidden as a Stage 5 Timeline disclosure class.

## S5-DISC-03 — Anonymous focus transition
**Status:** FROZEN

Timeline-eligible only when the transition is committed, historically legitimate, identity-free, and non-analytical. Emerging / provisional / pre-geographic shifts do not create Timeline markers merely because runtime attention moved.

## S5-DISC-04 — Timeline marker address
**Status:** FROZEN

Any approved Track marker is addressed from legitimate current-session `SP`, never `RTO`, `KF`, `VF/VT`, object age, Thread age, or Map position.

## S5-DISC-05 — Historical post-TC region
**Status:** FROZEN

While `PINNED(TC)`, `TC < position ≤ LH` may expose only non-metric reachability plus permitted Live meta. It must not encode future magnitude, count, density, semantic markers, subdivisions, focus stops, or accessibility enumeration.

## S5-DISC-06 — Live meta while historical
**Status:** FROZEN

May communicate only:
- Live continued / advanced;
- route back to Live exists.

Must not communicate future LF identity, Thread identity, location, direction, count, content, or analytical state.

## S5-DISC-07 — Accessibility parity
**Status:** FROZEN

Anything forbidden visually is also forbidden in screen-reader labels, announcements, focus order, child/set-size metadata, and accessible summaries. Exact final accessible control topology remains OPEN.

# 7. Stage 5.4 — Historical Projection + Map Temporal Appearance

## S5-HIST-01 — Truth changes; geography does not
**Status:** FROZEN

Projection changes may alter presence, state, version, contextual availability, renderability and lineage status. Projection changes never recompute established canonical spatial commitments.

## S5-HIST-02 — Independent resolution axes
**Status:** FROZEN

Keep separate:
- canonical identity knowledge;
- contextual appearance knowledge;
- version/state knowledge;
- then-current validity;
- default rendering;
- lineage/provenance retrievability;
- Semantic Zoom depth withholding.

Do not collapse them to a single visible/hidden boolean.

## S5-HIST-03 — Child components keep own temporal entitlement
**Status:** FROZEN

Relations, Evidence participations, contextual appearances, Confidence states/versions, Question/Information-Gap lifecycle changes, and other independently generated analytical units obey their own temporal entitlement. Parent availability never substitutes for child `KF` / validity.

## S5-HIST-04 — Known noncurrent lineage
**Status:** FROZEN

A known noncurrent version remains legitimate historical lineage but is not the default then-current Map representation.

```text
known ≠ then-current ≠ default-rendered
```

## S5-HIST-05 — Validity exclusivity
**Status:** FROZEN

A version lineage must not produce more than one then-current version at the same `TC`. Half-open `[VF, VT)` notation does not by itself guarantee gaplessness. Legitimate gaps must not be filled by borrowing another version.

## S5-HIST-06 — Emerging / Established lifecycle
**Status:** FROZEN

Emerging/pre-geographic Focus is provisional, is not automatically an Established Thread, and does not borrow future Home locus or create anticipatory geography.

Once established, `Active / Dormant / Reopened` are states of the same Thread identity and Home locus.

```text
Dormant ≠ absent
Reopened ≠ new Thread
```

## S5-HIST-07 — Contextual appearance
**Status:** FROZEN

A canonical object may remain legitimate through one context while another appearance is unavailable. Unavailable appearance does not mean object nonexistence, ownership transfer, or entitlement to future context leakage.

## S5-HIST-08 — Relation / geometry firewall
**Status:** FROZEN

Before a relation is legitimate: endpoints may independently exist, but no connector, pull, alignment, clustering adjustment, or proximity manipulation may be caused by future relation knowledge.

## S5-HIST-09 — Supersession
**Status:** FROZEN

If R1 was legitimately current at `t1` and R2 superseded it later:
- at `t1`, R1 remains then-current;
- later, R2 becomes current;
- R1 remains historical lineage;
- R1 is not automatically rendered beside R2 at ordinary Map depths.

Later correction does not rewrite earlier truth.

## S5-HIST-10 — Confidence
**Status:** FROZEN

Historical Map projection may expose only Confidence that is legitimately known, then-valid, and entitled at the current analytical depth. Confidence must not alter canonical geometry, distance, Home locus, or spatial importance.

## S5-HIST-11 — IF reference vs rendering
**Status:** FROZEN

Conceptually distinguish:

```text
IF_ref
IF_render
```

`IF_ref` remains exact unless an explicit user act changes inspection. `IF_render` is re-resolved against `K(TC)`. Unavailable future truth is never kept visible merely for continuity.

## S5-HIST-12 — Sparse historical viewport
**Status:** FROZEN

Projection change alone does not move camera. Sparse/empty historical geography may be correct. No auto-recenter, auto-zoom rescue, compaction, or placeholder rescue.

## S5-HIST-13 — Provenance
**Status:** FROZEN

At Source / Provenance depth, legitimately known historical lineage may be deliberately retrieved without forcing ambient higher-level clutter or leaking later provenance before its knowledge boundary.

# 8. Stage 5.5 — Temporal Orientation + Return Integration

## S5-ORI-01 — Five orientation dimensions
**Status:** FROZEN

Keep separate:
- temporal orientation;
- spatial orientation;
- inspection orientation;
- Live orientation;
- return orientation.

## S5-ORI-02 — Return actions remain distinct
**Status:** FROZEN

- Back One Step
- Return to Original Inspection
- Return to Live Head
- Return to Live Focus
- Return to World
- Go Live + Locate

Do not collapse them into generic Back/Home/Live/Reset.

## S5-RH-02 — Effective-change tuple
**Status:** FROZEN

```text
Φ_eff = ⟨ TM, TC, IF_ref, MC.region, MC.depth ⟩
```

Mode counts as an effective state difference even at equal temporal coordinates.

## S5-RH-03 — RH checkpoint payload
**Status:** FROZEN

Equivalent of:

```text
C_RH =
⟨ capturedTM_provenance,
  capturedTC,
  capturedIF_ref,
  capturedMC.region,
  capturedMC.depth ⟩
```

Restoration uses `PINNED(capturedTC)`, not literal mode replay.

## S5-RH-04 — Action-attributable no-op
**Status:** FROZEN

Passive Live evolution cannot make an otherwise no-op user command into an RH transaction.

> Passive events may change authoritative state, but they never give transaction authority to an otherwise no-op explicit command.

True no-op → no RH write.

## S5-RH-05 — Passive events
**Status:** FROZEN

New Live commits, LF changes, derived projection/`IF_render` re-resolution, and Preview pointer movement do not create RH entries by themselves.

## S5-RET-01 — Back One Step
**Status:** FROZEN

Back reverses the latest effective user-visible transaction. Temporal restoration always becomes `PINNED(capturedTC)`. Back never silently means “go Live.”

## S5-RET-02 — Return to Original Inspection
**Status:** FROZEN

Restores the named captured inspection checkpoint: `PINNED(capturedTC)`, exact `IF_ref`, exact contextual/lineage reference, exact camera, exact semantic depth. `IF_render` then obeys historical truth.

## S5-RET-03 — Return to Live Head
**Status:** FROZEN

Temporal-only:

```text
TM := FOLLOW_LIVE
TC := authoritative LH
```

It does not directly move camera or replace inspection reference. An effective Return Live preserves the pre-act historical checkpoint in RH.

## S5-RET-04 — Return to Live Focus
**Status:** FROZEN

Spatial-only one-shot:

```text
LF* := LF_at_activation
```

At settle:

```text
Locate iff Locatable(LF*, K(TC))
```

TC remains unchanged; later LF changes do not retarget the act; no persistent follow.

## S5-RET-05 — Return to World
**Status:** FROZEN

Spatial/depth only. Same temporal state. If already effectively at World and no action-attributable change occurs, no RH churn.

## S5-RET-06 — Go Live + Locate
**Status:** FROZEN

# POST-LIVE ONE-SHOT BINDING

```text
P5 activation
→ establish FOLLOW_LIVE
→ resolve authoritative Live Head
→ bind once:
     P5_LF* := LF_at_post-live-boundary
→ locate iff Locatable(P5_LF*, K(LH))
```

`P5_LF*` is transient, act-local, not a member of `S`, and not an intermediate RH checkpoint. If the bound focus is Emerging/pre-geographic or otherwise unlocatable, Live return succeeds and no fabricated camera landing occurs. LF changes after binding do not retarget the act. P5 remains one RH transaction.

## S5-RET-07 — Multi-locus contextual choice
**Status:** FROZEN

If P3 settles with multiple legitimate loci:
- temporal commit remains valid;
- no arbitrary camera move;
- later explicit context selection is a separate user-visible act and separate RH transaction if effective.

## S5-ORI-03 — Preview precedence
**Status:** FROZEN

Any committed return/navigation action during Preview first cancels Preview, discards PTC, writes no RH entry for Preview, and executes from authoritative committed state.
