# 1. Purpose

Stage 6.3 closes the minimum Map-side Experience decisions needed for a truthful, buildable v1 historical inspection experience.

The stage must answer:

1. how a present Established Thread reads as Active / Dormant / Reopened without changing identity or geography;

3. how much neighbourhood expression may vary with then-legitimate truth without looking like relayout;

- canonical identity;
- Home loci;
- historical projection;
- `IF_ref`;
- `IF_render`;

- Semantic Zoom;

# 8. OPEN-15 — Lifecycle-State Legibility

Stage 6.3 must decide the structural Experience language for:

- Active;
- Dormant;
- Reopened.

Required distinctions:

## Active
Present Established Thread in an active then-valid lifecycle state.

## Dormant
Present Established Thread at the same Home locus, but then-valid Dormant state.

Must NOT read as:
- absent;
- future-unavailable;
- deleted;
- rejected.

## Reopened
The same Thread has become active again after Dormancy.

Must NOT read as:
- a new Thread;
- duplicate identity;
- moved Home.

Resolve:

1. what structural channels may encode lifecycle state;
2. which channels are forbidden because they would alter geography/importance;
3. whether Reopened requires a persistent historical scar, transient transition cue, current-state cue only, or another bounded approach;
4. mobile/narrow perception;
5. accessibility/nonvisual state expression;
6. interaction with Semantic Zoom.

Do not freeze final colour/texture/motion unless semantically required.

# 11. OPEN-18 — IF_ref vs Rendered-Version Legibility

This is a perception problem, not a semantic one.

Example:

```text
IF_ref = R2
TC = historical t1
historically then-current/default Map render = R1
```

The runtime is correct.

But without Experience expression, the user may believe:

- QANDEEL lost their inspection;
- the system changed the selected object;
- R2 was overwritten by R1;
- the historical projection is broken.

Stage 6.3 must make the divergence legible while preserving:

- exact `IF_ref`;
- historically correct `IF_render`;
- no future leakage;
- lineage knowledge boundaries;
- Semantic Zoom hierarchy.

Resolve:

1. what structural state communicates “requested inspection retained, current historical render differs”;
2. how identity-known/version-unknown differs from known-noncurrent version;
3. how context-unavailable differs from version-unavailable;
4. how depth-withheld differs from temporal unavailability;
5. what may appear in return/inspection chrome;
6. what is available nonvisually;
7. what Source/Provenance may expose once legitimately known.

Do not keep future-unavailable content visible merely to reassure continuity.
