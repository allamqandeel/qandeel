# 2. Canonical Product Architecture

QANDEEL has:

> **one foundational Personal QANDEEL relationship**

plus:

> **two first-class intentionally discoverable Product Areas — Shared Worlds and Public World**

plus:

> **one intentionally discoverable optional high-trust capability — Introductions / التعارف**

The architecture is:

- Personal QANDEEL = foundational lived core;
- Shared Worlds = bounded relational Worlds for:
  - pre-existing relationships; or
  - newly initiated relationships created through successful `التعارف / Introductions`;
- Public World = first-class social/discovery Product Area around the Personal core;
- Introductions = optional, capability-owned, private-by-default, QANDEEL-mediated high-trust capability.

Conversation, Living Understanding and Analysis remain depths of the Personal Product domain rather than peer Product roots.

Sharing, Replay, Memory control, Explainability, Proactivity and authority controls remain contextual / cross-cutting responsibilities.

# 3. Canonical Global Shell

The authenticated App Shell is:

> **Personal-centered**

and:

> **immersive but never trapping**

Primary Global Switcher scope:

- `قنديل / QANDEEL`
- `العوالم المشتركة / Shared Worlds`
- `العالم العام / Public World`

`التعارف / Introductions` is not a fourth Global Area.

It remains:

- intentionally discoverable;
- capability-owned;
- reachable from Personal / secondary entry;
- reachable through valid Direct Entry.

# 4. Canonical Navigation Laws

## Global vs Personal canonical navigation

> **Global App Navigation ≠ Living Analysis Map Navigation**

The Personal Living Analysis Map remains canonical-state navigation, not a route stack.

## Global switching

> **switching ≠ pushing**

Global switching does not enter ordinary Global Back history.

## Back

> **Back is local-only**

At an Area's local root, Back does not silently return to Personal.

Canonical Personal Return semantics remain independent:

- `RETURN_LIVE_HEAD`
- `RETURN_LIVE_FOCUS`
- `GO_LIVE_AND_LOCATE`
- `RETURN_WORLD`
- `EXACT_RETURN`
- `BACK_ONE_STEP`

---

# 5. Canonical Restoration + Direct Entry Contract

Precedence:

```text
1. valid explicit Direct Entry
2. valid ordinary restoration
3. fresh/default Personal entry
```

Direct Entry must resolve:

- identity;
- validity;
- availability;
- authorization;
- owning Product context.

Area-owned targets enter through the owning Area's local navigation semantics.

Capability-owned targets enter the legitimate capability flow without creating another Global Area.

Invalid Direct Entry never guesses substitute objects.

---

# 6. Canonical Continuity / Scope Contract

Conversation/session continuity survives Area switching.

But:

> **relationship/session continuity ≠ live transport continuity**

Mic/audio/model streaming may suspend or stop safely.

Core law:

> **Area switch ≠ interaction/world reassignment**

Changing the visible Product Area must not change:

- canonical World ownership;
- interaction authority;
- audience;
- disclosure scope;
- reasoning scope;
- material authority;
- consent state.
