**Status:** dependency record for review. It freezes nothing and invents no runtime (brief §0, §29, §33).
**The finding first:** the repository contains **no canonical Voice / realtime runtime**. Every voice behaviour in G1.2
is therefore a Product-level proof over a simulated clock. This note says exactly what must exist before any of it can
run.

## 1. Voice Note — what history needs for truthful playback

| Need | Today | Consequence in the G1.2 proof |
|---|---|---|
| A durable, user-scoped audio object: storage, upload path, isolation, retention, deletion, encryption at rest | **none** (no media storage provider exists; Least Data / Least Retention applies) | the play control in history is **Product-proofed only**; nothing is stored |
| A Personal conversation-unit modality beyond `TEXT` | `source_modality` is CHECK-pinned to `TEXT` | a committed note cannot be a canonical unit today; the proof shows it as the reader's `UTTERANCE` anyway, as a Product target |
| Measured duration | a client fact at capture | shown (it is true of the capture) |
| A textual representation (transcript) | **no STT runtime** | **no transcript is shown**; a waveform is not drawn either, because it would be invented data |
| A local draft store for a capture stopped by leaving QANDEEL (R-VN) | not built | a draft in memory in the proof |

**Decision G12-J2** (for review). The G1.1 closure wording "a voice-message turn with its committed textual
representation" presupposes a text representation. If the product wants one, it needs three things:

- an STT step behind the Voice Adapter;
- a provenance line that says it is a machine transcription;
- no verbatim typography (VI-01 §18: recorded material is never quoted as verbatim).

If the product does not want one, the committed note is media plus its duration, as proved here. **A transcript is
never a substitute for the audio** (brief §29).

## 3. Background continuation — what must exist

- **The native call lifecycle:**
  - iOS: CallKit (outgoing), `playAndRecord` / `voiceChat` and the `audio` background mode;
  - Android: Core-Telecom and its foreground execution, the ongoing-call notification, and the Play declaration.
  - Details and sources: the compliance note.
- **One in-process call controller** owning `callId`, the Conversation id, mute, route and **the last visible in-call
  surface**. The restore rule is implemented here: backgrounding and returning never write the surface. No persistence
  is needed or wanted:
  - a live call and its surface die together with the process, and a relaunch must not pretend otherwise;
  - T-13's durable viewpoint is unaffected (the in-call surface is ephemeral).
- **No new background work.** The Analysis live driver stays foreground-only (T-12P) and catches up on return. In the
  background the only work is the call's own audio transport. This is what keeps the background capability legitimate
  (compliance note §1.4, §3).
- **End convergence:** every system end path (CallKit End, notification Hang up, Bluetooth, Task Manager) reaches the
  same controller (compliance note §7).

## 4. Replay original audio

- **Personal original audio / call:** NOT PRODUCIBLE (`replay-runtime-v1` §7). An ongoing call is open Live Head and
  cannot be frozen (§19). The proof's Replay entry during a call therefore says «المكالمة الجارية غير مشمولة.», and a call
  marker is never a selectable Replay turn (check **G12-R1**).
- **Before an audio-led Replay can launch,** the Voice / Live Call track must establish a reviewed, durable, consented,
  retention-bounded Personal original-audio / call source (G1.1 closure §5). The original audio must be recorded
  truthfully. A transcript or a re-synthesised voice is **not** the original audio, and `replay-runtime-v1` already
  forbids promoting one to it.
- **The Shared `HUMAN_VOICE_NOTE`** has digest-level source identity only; its media delivery is not claimed.

## 5. Provider / runtime gaps

1. **No canonical Voice runtime document exists.** G1.2 keeps to Product level, as the brief requires.
2. **The Voice Adapter and Speech Rendering** are named but not implemented. No provider is chosen, and G1.2 chooses
   none.
3. **No backlog item owns the Voice / Live Call runtime.** `QAN-BL-NAV-02` covers the Replay surface only.
   - *Recommendation for G1.2's closure change* (not made here, because tracked files are untouched): admit one item
     for the Voice / Live Call runtime. It would carry this note's §1–4 needs, the store declarations (compliance note
     §11), and decisions **G12-J2, J4, J6, J7, J8** as its inherited residue.
4. **The VI-01 voice strings are Phase VII.**
5. **Device validation** of every OS-owned path (compliance note §5, §7) is a spike and device gate.

## 6. What can be Product-proofed now (this package)

- **The three ways of talking:** their controls, their Conversation-first / Analysis-first defaults, and their words.
- **The call life-cycle as the reader sees it:** connecting → live (the reader speaking / QANDEEL speaking / muted) →
  reconnecting → the same call, or failed → Writing; the reader ending it.
- **The background rule:** the same call through lock and another app; return to the exact last surface; a truthful
  return after the call ended away; a force-quit relaunch without fake continuity.
- **Permission at intent, and denial → Writing.** The Voice Note capture / cancel / commit / playback and the
  leaving-mid-capture draft.
- **The Analysis law:** it changes on commit, not with sound. Replay coexistence.
- **Reduced Motion parity, and the bilingual, Light, contrast and 200% states.**

## 7. What must exist before production

1. Voice Adapter + a benchmarked provider path + Speech Rendering (Tech Stack gate order: text path first).
2. The native call-lifecycle layer and the audio session / FGS / notification (compliance note §1–4), with the §11
   declarations and nothing more.
3. The server `callId`, spoken-turn commits into conversation units, the interruption semantics, the reconnection window.
4. A durable Personal audio source and a non-`TEXT` modality, if voice notes are to be replayable or Replay is to be
   audio-led, with consent, retention and deletion.
5. The decisions G12-J1…J10 (final report §O).
6. Real-device validation: VoiceOver / TalkBack, the OS call surfaces, lock / unlock, Bluetooth, other-call
   interruption, Task Manager, notification denial.
