### What each one changed

- **emil-design-eng → the line enters as an opacity resolve in place and never travels on its own; the exit is
  faster than the entry.**
  - It has no translate. The skill's point that enter and exit share one path meant the line's only movement is the
    Timeline's own. Motion that just looks nice has no purpose here: this is a place readers pass through often.
  - **Entry and exit:** 220 ms in, 140 ms out, on T-10's one ease-out curve.
  - **Shell tone change:** 200 ms, under the skill's 300 ms UI ceiling. It is not tied to the longer depth travel,
    which runs 320 ms after a 100 ms delay.
  - **Checked by:** K23 (in every frame of clips 01, 02 and 05, the line sits at one constant offset from the Track) and
    K21.
- **designing-arabic-frontends → the line keeps the chrome's Arabic typography and start inset, and its digits
  follow the one product-wide policy.**
  - **Typography:** `r-support`, a line-height of 1.667, which is ≥ 1.6 (§2), and no letter-spacing (§5).
  - **Start inset:** 24 pt from the start edge, the same inset as the status line it replaces. It starts at the
    right in Arabic and the left in English. The Live-edge act stays at the END edge.
  - **Digits:** the Moment number stays in Western digits, pinned product-wide by T-12 §9 (a recorded decision, §3).
    It sits inside an Arabic sentence with no LTR island, because a number alone needs none (§4).
  - **Checked by:** K26 (leading and letter-spacing on every rendered line) and K27 (English starts at the left, the
    Live edge is at the right; the Arabic mirror; cross-script paragraphs unchanged).
- **fixing-accessibility → the Live-edge act's box was cut to its label row, and the line is text that the slider's
  reading order passes through, not a focus stop.**
  - **The act's box.** The skill's rule that a focus indicator must stay visible and unobscured exposed a real
    overlap. G3.1's 88-pt Live-edge box would have enclosed the moved line, so its focus ring would have crossed the
    sentence (finding F-02).
    - The box now starts at the label row, 60 pt, and the label does not move.
  - **The line.** It is the Timeline's first child. DOM order is reading order is visual order: the line, then the
    slider, then the Live-edge act, then «طرق العودة».
  - **Kept unchanged:** `aria-expanded` / `aria-controls`, and focus return on Escape.
  - **Checked by:** live steps in B-PINNED (DOM order, Tab order, overlap, expanded state, focus return, ≥ 44 × 44 pt)
    and K25.
- **animate-expo → port notes recorded, no Expo code written.**
  - **The status bar:** on a device it is a surface-scoped style, light content while the Analysis is shown under
    system Light. It is switched by the platform and cannot be cross-faded the way the proof's HTML status row is.
    Finding F-07 routes that to the implementation owner.
  - **The line:** in the port it is an `entering` / `exiting` opacity layout animation with
    `reduceMotion: ReduceMotion.System`. The skill's rule applies: under Reduced Motion keep the opacity that explains
    the state and drop the travel. The proof does this: a 140 ms resolve in, and a cut out.
- **apple-design → one immersive place gets one material, and the surface boundary is where the tone changes.**
  - **The shell.** The skill says to keep material consistent within a place and to ease dark ↔ light changes rather
    than jump. So the Analysis shell (status, rail, call line, home indicator, ground) takes the dark scope as a
    whole, never piece by piece. Its tone eases over F2's 200 ms cross-fade.
  - **Where F2 wins.** F2 removes the appearance cross-fade under Reduced Motion. The skill suggests easing brightness
    changes, but canon wins over the skill here, so under Reduced Motion the tone change is a cut. This is recorded,
    not hidden.
  - **Checked by:** K17, K21 and live steps A-LIGHT / A-LIGHT-CALL / RM.
