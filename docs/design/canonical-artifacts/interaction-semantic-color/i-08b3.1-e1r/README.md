# I-08B3.1-E1 — INTERACTION + SYSTEM SEMANTIC COLORS

**Revised by I-08B3.1-E1R — TARGETED INTERACTION / STATUS CONTRACT CORRECTION.**
**Freeze candidate. Frozen by nobody.**

---

## The short version

QANDEEL already said what things are made of (**Living Brass**) and what the system
understood (**QANDEEL Light**). E1 says where the **user** is, and what needs **attention**.

```
STATE IS THE USER'S POSITION.      and it introduces NO colour at all.
STATUS IS WHAT NEEDS ATTENTION.    a hue is EARNED, and so far only failure has earned one.
```

**E1 adds exactly one colour to QANDEEL** — the error ink `#fe907e` — plus one extension of
the frozen reading ramp for the unavailable state, `#696762`, derived from the ramp by the
ramp's own rule.

Press, focus and selection are expressed entirely in the Product's own frozen neutrals, in
geometry, in type weight and in behaviour.

---

## What I-08B3.1-E1R changed

**No token value moved and no accepted expression was redesigned.** Four sentences frozen as
Product contract were corrected, one stylesheet rule was removed, and one state combination
that had been declared impossible now has an expression.

| | |
|---|---|
| **REV-01** | an unavailable control was frozen as never focusable. **DISABLED describes AVAILABILITY**; two control patterns now ship, visually identical, differing only in focus-order membership |
| **REV-02** | the exclusivity rule about visual channels was **false** — SELECTED writes the ink and so does DISABLED. Replaced by a composition / ownership model with three precedence rules and all sixteen combinations enumerated |
| **REV-03** | the **number** of status hues was frozen as a cap. **STATUS COLOUR IS EARNED**; the count is not frozen, the earning is |
| **Brass** | a universal navigation and entitlement law with no canonical authority behind it, narrowed to what is actually frozen: **the material is state-invariant in value and in appearance** |

`docs/E1R_REVISION_RECORD.md` is the one document that quotes the withdrawn wording.
`docs/E1R_PRODUCT_SURFACE_AUDIT.md` is the bounded audit that tested the status policy
against eight real QANDEEL surface categories — **and found two of its three refusals had
already met their own overturn condition.** Neither is answered with a colour; both are
handed to Product.

## Layout

```
docs/     the argument, the contracts, the gates, and the generated results
tokens/   DTCG 2025.10. Authored by E1. GENERATED by tools/e1-tokens.mjs
vendor/   inherited from B4R, C3 and D2R, byte-identical, digests in data/E1_VENDOR.json
review/   15 proof boards
tools/    the derivation, the emitter, the scene, the render, the suites
data/     every number this package states, as JSON
fonts/    Estedad v8.5, the frozen typeface
```

`tools/e1-composition.mjs` holds the Product statements I-08B3.1-E1R added — the channel
ownership, the precedence rules, the availability patterns, the sixteen-row matrix and the
status policy. They are **emitted into the shipping token file**, and every check reads them
back from there rather than from the module, so a check cannot pass by agreeing with the
code that wrote it.

## Reproducing it

Node 24 and Chrome. From the package root:

```
node tools/e1-tokens.mjs       # derive the two values and emit the token files
node tools/e1-render.mjs       # render the 12 boards and derive the 3 transforms
node tools/e1-focus.mjs        # drive real Tab and Enter events through Chrome
node tools/e1-skills.mjs       # the Skill Gate
node tools/e1-verify.mjs       # 32 checks, 32 probes
node tools/e1-consistency.mjs  # read the shipped artefacts back and check they agree
node tools/e1-docs.mjs         # regenerate the results, the gate and the manifest
```

`e1-verify.mjs` layer A runs with none of the others and with no project root: the claims
that matter most survive the barest environment.
