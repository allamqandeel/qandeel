## 1. The historical constitution (frozen Stage 6.5 v3 / 6.6 v3, REV66-06 .. REV66-08, R-C1 .. R-C5)

| Rule | Meaning |
| --- | --- |
| ONE COMMITTED CU = ONE MOMENT | `SP` is the gapless per-Session ordinal of a committed CU; `LH` the greatest committed `SP`; `TC` the effective selected Session Position, `1 <= TC <= LH`. |
| SP-native availability (R-C4) | Every exposed component of a Session's history receives its own `PRE_FIRST_SP \| SP(n)` anchor through the Session Semantic Clock and the ONE 0065 same-SP seam, or through the Session's baseline. A timestamp is never an anchor. |
| Actual availability, never causal source | A fact is anchored at the Session Position at which it became canonical in that Session, never at the Moment that "caused" it. |
| Server-owned Session association | The durable post-response execution (owner, Session, source turn) is the ONE association. A caller-supplied `session_id` is not authority. A fact without a server-owned association is UNASSOCIATED: it carries a world version only, is never untracked, never receives a fabricated anchor, and enters a later Session only through that Session's baseline (REV66-06 §4.5). |
| Coverage (R-C1) | Every Session that existed before 0072 is a LEGACY UNCOVERED SESSION: its Conversation Runtime continues normally (committed CUs, Session Positions, `LH`, the frozen T-03B / T-03D chain and the T-03A2 / T-03D live reads), but it stays historical-disabled through closure — no baseline is ever cut for it, post-deploy capture retained internally upgrades nothing, and the projection fails closed at every `TC`, so no partial Timeline and no PINNED historical semantics ever become addressable. Coverage gates historical projection, never runtime. A Session created after 0072 is COVERED at creation. A Session is never partially historical. |
| Baseline / PRE_FIRST_SP | `baseline(S)` is the per-user World Semantic Clock version read under its row lock at the commit of `SP(1)`. Everything unassociated with `world_version <= baseline(S)` is known at every `TC` of `S` (`PRE_FIRST_SP`); everything later never enters `S`. There is no race gap with `SP(1)`. |
| Preservation (R-C2) | No canonical Reading, Material, Question candidate or Confidence row can be deleted; no identity, provenance or lineage column can be rewritten in place; only the lifecycle columns move. No history row is ever updated or deleted; the world clock never regresses. |
| Tracked attach paths (R-C3) | Every write to `public.hypotheses` — whatever its path (0005, 0008, 0021, 0028, the managed commands) — passes the ONE capture hook; no untracked Evidence participation can be authored. |
| Expiry (R-C5) | `expires_at` is a wall-clock policy fact. It is never compared to `TC`; it is mapped into Session Position space (`NO_EXPIRY \| PRE_FIRST_SP \| SP(n) \| PENDING \| NOT_IN_SESSION`) with half-open intervals `t(n) <= X < t(n+1)`; an exact tie is EXPIRED at `n`. Expiry never advances `LH`, never moves `TC`, never writes `RH`, never erases identity or lineage. |
| Three absences kept apart | Historically unavailable (`UNKNOWN_AT_TC`, `CONTEXT_UNAVAILABLE_AT_TC`) ≠ known but noncurrent (`KNOWN_NONCURRENT_AT_TC`: `PREVALID` / `SUPERSEDED`) ≠ withheld at this depth (`AVAILABLE_BUT_DEPTH_WITHHELD`) ≠ not fetched (client, Class B). A technical gap fails closed (Z66-05) and is never `UNKNOWN_AT_TC`. |
| No kernel write, no RH | `K(TC)`, `V`, `IF_render`, divergence and the footprint have no key in the T-02 `CanonicalState`; no Product action and no `RH` entry is ever produced by a projection. There is no generic `WORLD_TRUTH_UPDATED` event. |

## 2. Architecture decisions

**D-01 — A per-user World Semantic Clock.** `historical_world_semantic_clocks(user_id, current_version)` advances by exactly one per capture context, under its row lock. It orders unassociated facts for baselines; it is never a Session Position and never appears on the wire as a temporal authority.

**D-02 — Coverage decided at creation; runtime never gated; the SP(1) baseline for COVERED Sessions only.** The migration decides every existing Session `LEGACY_UNCOVERED`; an `AFTER INSERT` hook on `conversation_sessions` decides every new Session `COVERED`. Committed-CU runtime eligibility and historical projection eligibility are different things: nothing on `conversation_units` consults coverage, so a LEGACY UNCOVERED SESSION keeps committing CUs and Session Positions through the frozen runtime authority. The ONE 0072 hook on `conversation_units` (`AFTER INSERT`) cuts `session_historical_baselines` at `session_position = 1` for a `COVERED` Session only, from the world clock read `FOR UPDATE` (the lock is held to commit, so the cut is exact) — a LEGACY UNCOVERED SESSION, or a Session without a coverage decision, never receives a baseline, which is what keeps the projection fail-closed for it through closure — and anchors the Formal Question ↔ Turn appearance of the exchange at that exchange's first committed Moment (D-07). Targeted revision R1-01: the original build carried a `BEFORE INSERT` coverage gate that refused committed CUs for legacy Sessions; that disabled the Conversation Runtime, which the frozen contract never authorized, and it is removed.

**D-03 — ONE capture boundary, clock-first (AF66-01).** `historical_capture_begin_v1(user, session | null, require)` establishes a transaction-local context `{ user, requested session, associated session | null, SP | null, same-SP sequence | null, world version }`: Session Semantic Clock `FOR UPDATE` → the ONE 0065 seam `reserve_session_same_sp_event_v1` (only while an addressable `SP` exists) → World Semantic Clock `FOR UPDATE`, `+1`. One context per (user, requested Session association) per transaction. Every capture hook reads the newest context of the writing user through `historical_capture_context_v1`; a write without one is UNASSOCIATED and receives a world-only context — never an untracked write, never a fabricated anchor. No caller can supply an `SP`, a sequence or a world version. A Session of another user is `HISTORICAL_CAPTURE_ASSOCIATION_INTEGRITY`.

**D-04 — The durable execution is the association; wrappers, not rewrites.** The three managed commands keep their public names, signatures, results and `service_role` grants: their frozen 0034 / 0035 / 0036 bodies live on under `*_core` (executable by NO application role) and the public names are wrappers that call `historical_capture_begin_for_execution_v1(p_execution_id)` (owner + Session from `post_response_intelligence_executions`) and then the core. `sync_post_response_information_gaps_v1` keeps its name and its v2 delegation with the same first step. `server_create_memory_for_execution_v1(p_source_turn_id, …)` derives owner AND Session from the RUNNING execution that owns the source turn with `MEMORY_WRITE` claimed, then runs the frozen 0026 command; the TypeScript background Memory writer calls it instead of naming a user id. Every existing caller and every historical verifier enters the boundary unchanged.

**D-05 — Typed per-family history with deterministic identities.** Eight append-only event tables (`historical_reading_events` with `CREATED / STATUS_TRANSITION / VERSION_ADVANCED`, `historical_evidence_participation_events` `ATTACHED / DETACHED`, `historical_reading_relation_events` `LINKED / UNLINKED` over one unordered pair, `historical_material_events`, `historical_gap_events` `CREATED / CLOSED / REOPENED` by epoch, `historical_question_events`, `historical_confidence_events`, `historical_question_appearance_events`) plus `historical_thread_availability`, each row carrying the ONE anchor shape `(session_id, session_position, same_sp_event_sequence, world_version)`. Identities are RFC 4122 v5 through the frozen 0068 authority over `79466f6b-04fd-5150-aa23-59682098057c` = uuidV5(URL, `https://qandeel.app/runtime/historical-availability-event/v1`); an identity reused with a different payload is `HISTORICAL_EVENT_IDENTITY_CONFLICT`, an identical retry duplicates nothing. The migration seeds a `LEGACY_BASELINE` event (world version 0, no Session anchor) for every pre-existing canonical row and writes nothing else.

**D-06 — The Thread ↔ Reading appearance substrate, derived in production (R2).** `thread_reading_bindings(binding_id, session, thread, reading, bound_sp, unbound_sp, …)`: identity uuidV5(`11be3a36-745a-54fd-a938-3f14eaedee14` = uuidV5(URL, `https://qandeel.app/runtime/thread-reading-binding/v1`), `session:thread:reading:boundSp`), idempotent, unbound by ordinal, one life per Session Position (`THREAD_READING_BINDING_IDENTITY_CONFLICT`). The ONE recorder `record_thread_reading_appearance_v1(user, session, thread, reading, sp, sequence, world version)` takes its anchor from the production authority that derives the appearance (D-14) and is executable by no application role; `bind_reading_to_thread_v1` / `unbind_reading_from_thread_v1` (clock-first through the boundary, association REQUIRED) stay granted to NO application role and have NO production call site — no server module, evaluator or client ever decides a binding. **R1-02 RESOLVED (R2) — CANONICAL READING SUBJECT-GROUNDING AUTHORITY.** The frozen rule binds a Reading to a Thread only when the Reading's subject grounding legitimately resolves to that Thread / focus. The original build found that the repository carried no server-owned canonical subject grounding for a Reading: `public.hypotheses` (0005) carries `statement`, `type`, `domain`, `scope` (free text; `CONVERSATION_SESSION:<session>` for generated Readings), `origin`, the lifecycle columns and the three arrays, and no later migration adds a column; the only relations to a Hypothesis were Confidence (0006), `information_gap_hypotheses` (0007), `hypothesis_updates` (0008), lifecycle transitions (0036), Gap sources (0038), formal Question bindings (0063) and the 0072 history — none named a reference handle, an Emerging Focus or a Thread; the generation intent and the candidate proposal carried none either. Binding from a label, string similarity, an embedding, Evidence or peer co-occurrence, the current LF at creation time, or geometry is forbidden by the frozen rule, so none is invented: R2 adds the authority itself (D-14) — reusing the frozen B1 focus identity and the 0070 focus → Thread binding — and the appearance is now DERIVED from it inside the database, so A-1 is FULL AFTER BUILD through a production path, never through a heuristic and never silently. This was the one gap the canonical repository revealed against the Stage 6.6 v3 matrix (A-1 names a `thread_reading_bindings` equivalent that did not exist); T-03C fills the substrate, owns the truthful history of the appearance and its projection, and invents no Product semantics.

**D-14 — The canonical Reading subject-grounding authority (R2): ontology, universe, proposal, authorization, atomic persistence, derived appearance.** *Ontology.* Stage 1.9 freezes Reading ↔ Hypothesis as PARTIAL; T-03C keeps the four layers apart: (A) analytical identity — the canonical `public.hypotheses` row, unchanged; (B) subject grounding — `hypothesis_subject_groundings(grounding_id, hypothesis, session, emerging_focus, execution, source turn, universe_frontier_sp, session_position, same_sp_event_sequence, world_version)`, identity uuidV5(`1592a69d-781e-57ce-bb2c-6744a6ac3ceb` = uuidV5(URL, `https://qandeel.app/runtime/hypothesis-subject-grounding/v1`), `hypothesis:focus`), one per (Reading, focus), targeting exactly a canonical B1 Emerging Focus (0066) — the identity Threads are constituted from (0068 / 0070) — so no new Thread constitution and no new focus identity exist; (C) Thread appearance — `thread_reading_bindings`, derived (D-06); (D) Evidence participation — the tracked events of R-C3, never a grounding. *Universe.* `build_hypothesis_subject_grounding_universe_v1(execution)` (`service_role`, RUNNING execution only) builds ONCE per durable execution, from committed truth alone — the execution's Session's Emerging Focuses (0066) with each focus's first committed RESOLVED wording, `startedSp`, last attention SP and the Thread it already resolves to (0070) — bounded to 32 by recency, frontier = the immutable causal semantic frontier of the execution's own source finalized exchange (D-15), stored in `hypothesis_subject_grounding_universes` and presented to the provider as opaque handles only: handle = uuidV5(`8feaee1d-fe51-5e9e-8594-52499b414e64` = uuidV5(URL, `https://qandeel.app/runtime/subject-grounding-handle/v1`), `execution:focus`), the wording and the Session Positions; no focus, Thread, Session or CU identity crosses to a provider. *Proposal.* The dispatcher builds the universe from the durable execution before the CANDIDATE_PROVIDER claim; the Gemini request carries `eligibleSubjectGroundings` and the response schema allows `subjectGroundingHandles` as an enumeration of exactly the issued handles (at most 8 per candidate; the field and its instruction exist only when the universe is non-empty, so a request without one is the frozen request byte for byte). *Authorization.* The pure server authority (`hypothesis-subject-grounding.authority.ts`) admits only handles issued for this execution's universe — set membership, never wording, Evidence, LF or geometry — and refuses malformed, duplicate, over-long or foreign handles with typed reasons (the candidate fails; it is never silently un-grounded). `complete_post_response_grounded_candidates_v1(execution, code, payload, selections)` runs the frozen 0033 completion FIRST, then judges the selections against the STORED universe (`SUBJECT_GROUNDING_UNIVERSE_MISSING`, `_TARGET_NOT_CANDIDATE`, `_LIMIT_EXCEEDED`, `_DUPLICATE_HANDLE`, `_HANDLE_OUTSIDE_UNIVERSE`, `_PROPOSAL_CONFLICT`); a refusal rolls the completion back with it, and `NO_ACCEPTED_CANDIDATES` carries no grounding. *Persistence.* The frozen `persist_post_response_hypothesis_generation_v1` wrapper runs its `_core` and, when it persisted, `persist_authorized_subject_groundings_v1` in the SAME transaction under the SAME execution association: each grounding is anchored at the capture context's Session Position (actual availability — the Live Head at persistence — never the focus start, never the causal source turn), re-resolved through the stored universe (`_TARGET_MISSING`, `_ANCHOR_UNAVAILABLE`, `_FOCUS_NOT_CANONICAL`, `_IDENTITY_CONFLICT`), idempotent on a durable retry. *Derived appearance (A-1).* Two `AFTER INSERT` triggers are the ONLY production authors of an appearance: on `hypothesis_subject_groundings` (Case A: the focus already resolves to a Thread bound at or before the grounding's SP → an appearance at the grounding's own anchor) and on `conversation_thread_focus_bindings` (Case B: a focus grounded while Emerging becomes a Thread → an appearance at the binding's own Session Position and Thread-layer same-SP sequence; nothing is backdated). A Reading grounded to N legitimate focuses appears in N Threads under ONE analytical identity; Dormant / Reopened / Active change no appearance and no Home; an Evidence attach changes nothing; a legacy Hypothesis (no execution, no universe) has no grounding and no appearance, ever; an AMBIGUOUS reference is no focus and can never be grounded. The projection discloses `readings[].subjectGroundings` (`emergingFocusId`, `groundedAtSp`) under the ONE availability law and the appearance exactly from its own bound SP (P66-D).

**D-15 — The deterministic causal grounding frontier (R3).** Two boundaries stay separate. The **causal input frontier** answers "which committed conversational Focus truth is legally eligible to inform THIS post-response generation?"; the **canonical availability anchor** answers "at which SP does the newly authorized grounding actually become canonical?". Only the second is the capture context of D-14; the first is what the universe is cut at, and it must be immutable. A durable execution belongs to exactly ONE finalized exchange — the COMPLETED USER source turn its `ConversationTurnCompleted` event named (0019) and the COMPLETED ASSISTANT turn finalized as its response — and the foreground runtime publishes that event BEFORE the FINAL semantic establishment of the exchange has run, while the background dispatcher consumes it independently. The Session's Live Head is therefore NOT that authority: it is behind the exchange before establishment completes (an early worker would store an empty/stale universe) and ahead of it once later exchanges commit (a delayed worker would see later focuses and later attention), so three schedules of one execution would produce three different subject-grounding truths. `post_response_source_causal_frontier_v1(execution)` derives the frontier from the durable FINAL chain instead: FINAL semantic establishment is complete for a source turn exactly when the LAST layer of that chain — the effective Live Focus commitment batch of 0071 — is durably recorded for a commitment batch of that turn, and `causal_frontier_sp` is then the greatest Session Position the exchange ITSELF committed, read from the committed-CU delivery events of 0065 (`last_sp`). Both are append-only historical facts of exactly that exchange, so they can never move. Inside the cut, `started_sp`, the attention behind `lastAttentionSp`, the committed reference wording used as `subjectText` and the focus → Thread resolution stored in the universe row are ALL capped at `causal_frontier_sp`; nothing born after it is visible to the provider, and a Thread that did not exist by then is not in the universe at all. Two conditions are kept strictly apart: a source exchange whose FINAL semantics are **not established yet** builds and stores NOTHING and answers `SOURCE_SEMANTIC_FRONTIER_NOT_ESTABLISHED` — a stable technical refusal the dispatcher treats as retryable (no universe row, no Candidate claim, no provider budget slot, zero provider calls, non-terminal so the existing bounded delivery policy retries) — while an exchange that IS established and truthfully contains no groundable canonical Focus has a valid, durably stored EMPTY universe. A FINAL-established exchange that committed no Conversational Unit at all allocated no Session Position, so its universe is empty by the same rule: deliberately conservative, it can only ever under-ground, never expose truth from outside the causal cut. The grounding's own availability is unchanged and is never backdated: the causal source may be earlier (`causal_frontier_sp` = n) while the canonical grounding `KF` is the SP it actually persisted at (n + k), and the derived A-1 appearance follows the grounding, never the causal frontier and never the Thread's earlier establishment.

**D-07 — The Formal Question ↔ Turn appearance anchors at the exchange's first committed Moment.** A binding becomes `BOUND` at `finalize_conversation_turn_v2`, before the exchange's CUs are committed; anchoring it at finalization would need a Session Position that does not exist yet or a lock taken out of AF66-01 order. The appearance is therefore captured by the SP(1) hook of D-02 at the first committed CU of the same exchange (user or assistant turn), at same-SP sequence 0, identity `question-appearance:<binding_id>`. `SELECTED` is a transient reservation and `RELEASED` a non-appearance; neither is exposed.

**D-08 — R-C5 as ONE STABLE mapping.** `historical_memory_expiry_at_sp_v1(session, expires_at)` with `t(k) = max(created_at of committed CUs with sp <= k)`: `NO_EXPIRY`; `PRE_FIRST_SP` when `X < t(1)`; `SP(n)` when `t(n) <= X < t(n+1)` (an exact tie is EXPIRED at `n`); `SP(LH)` when `t(LH) <= X <= now` and the Session is open; `NOT_IN_SESSION` when the Session closed before `X`; `PENDING` when `X` is in the future. The projection consumes the mapping and marks a Material `EXPIRED` at `TC` iff the mapped `SP <= TC` (or `PRE_FIRST_SP`); identity and lineage stay known. The projection itself reads no timestamp.

**D-09 — Preservation by guard.** `guard_historical_canonical_row_preservation_v1` refuses `DELETE` (`CANONICAL_HISTORICAL_ROW_IS_PRESERVED`) and any rewrite outside the lifecycle columns (`CANONICAL_HISTORICAL_FIELD_IS_IMMUTABLE`: Reading `status / version / updated_at / supporting_evidence_ids / contradicting_evidence_ids / competing_hypothesis_ids`; Material `status / updated_at`; otherwise `updated_at`). Every history table is append-only (`CANONICAL_HISTORICAL_ROW_IS_IMMUTABLE`); the world clock is `WORLD_SEMANTIC_CLOCK_IS_PERMANENT / MONOTONIC`.

**D-10 — R-C3 by capture, not by breaking live callers.** `attach_hypothesis_evidence` (0005), `apply_hypothesis_evidence_update` (0008) and `background_attach_hypothesis_evidence_v1` (0021 / 0028) are live production callers (the authenticated Hypothesis endpoint and the background data API). They keep their object identity and grants; every write they make to `public.hypotheses` passes the ONE capture hook and authors exactly one TRACKED participation event — unassociated (world-only) because they carry no server-owned Session association — so the old bypass can no longer author untracked Evidence participation, and no fabricated Session anchor exists. The verifier proves it per path.

**D-11 — Layer A: ONE owner-scoped, coverage-gated, fail-closed projection.** `get_session_historical_projection_v1(session, tc)` (STABLE SECURITY DEFINER, `auth.uid()`): `FORBIDDEN` for a Session the caller does not own; `HISTORICAL_COVERAGE_UNAVAILABLE` for a LEGACY UNCOVERED SESSION; `LIVE_HEAD_NOT_ESTABLISHED` before `SP(1)`; `SESSION_POSITION_NOT_ADDRESSABLE` outside `[1, LH]`; `HISTORICAL_BASELINE_MISSING` for corruption. Every family is projected by its own anchor under the ONE availability law; then-current status / version / epoch is the latest known event; relations, participations, Confidence and appearances require BOTH endpoints known; Thread lifecycle at `TC` comes from the durable 0070 history, `LF` at `TC` from the durable 0071 history, the ONE Home from `conversation_thread_homes`; Confidence resolves `CURRENT / SUPERSEDED / PREVALID` against the then-current version (Z66-04). No current mutable row is ever a historical fallback. The result is byte-stable for a sealed `TC` and evolves only at the open head.

**D-12 — Layer B: pure server disclosure over the five frozen rungs.** `disclose(K, depth, inspection)` discloses exactly the rungs at or below `depth` (WORLD: Threads + LF; THREAD: + Thread ↔ Reading appearances; SESSION: + Moments, Emerging Focuses, Formal Question ↔ Turn appearances; ANALYTICAL_OBJECT: + Readings, relations, Materials, Gaps, Questions, Confidence; SOURCE_PROVENANCE: + Evidence participations); a rung above is `DEPTH_WITHHELD`, never empty. Reading discloses at the analytical-object rung, never a depth of its own. An inspection is answered along three orthogonal axes: knowledge (`UNKNOWN_AT_TC`, `KNOWN_AND_CURRENT_AT_TC`, `KNOWN_NONCURRENT_AT_TC` with `PREVALID` / `SUPERSEDED`), context (`NOT_REQUESTED`, `CONTEXT_AVAILABLE_AT_TC`, `CONTEXT_UNAVAILABLE_AT_TC`) and disclosure (`AVAILABLE_AND_RENDERABLE`, `AVAILABLE_BUT_DEPTH_WITHHELD` with the required depth). Threads carry `ESTABLISHED_ACTIVE / ESTABLISHED_DORMANT / ESTABLISHED_REOPENED / ESTABLISHED_UNBOUND_IN_SESSION`; Emerging Focuses `EMERGING_PREGEOGRAPHIC`. `K(TC)` never leaves the server.

**D-13 — Additive wire, passive client, frozen kernel.** `packages/runtime/src/historical-projection.d.ts` declares `V` (typed per rung, `HistoricalRung<T>`, no timestamp, no same-SP sequence, no score, no label, a Home as exact integer text). `apps/mobile/src/projection/` validates it at runtime (exact keys, depth-monotonic rungs, `SP <= TC <= LH`, closed vocabularies), fetches it through ONE injected-fetch route bound to the requested Session / TC / depth, and holds it as Class B with `NOT_FETCHED` ≠ `FETCHED` (with `UNKNOWN_AT_TC` / `DEPTH_WITHHELD` inside) ≠ `UNAVAILABLE` (the typed refusal). Nothing writes the T-02 kernel, dispatches a Product action, appends `RH`, moves the camera or is mounted. The kernel, the shell, the router root and the T-03A2 / T-03D temporal seam are byte-identical.
